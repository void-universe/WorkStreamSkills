# 本地渲染交接规范

给「把分镜交给本地渲染器」用的通用约定。渲染器跑在**谁的机器上、用什么模型**由部署方决定；这份规范只约定
**怎么交活、怎么验收**，不绑定任何具体实现。

**执行器**：[WorkStreamRenderer](https://github.com/void-universe/WorkStreamRenderer)（本机渲染脚本，无凭据）。

## 交接协议

1. 你在群里（或仓库里）上传一份名为 `分镜.json` 的文件。
2. 渲染器按约定轮询它，发现就逐条渲染。
3. 渲完回一份 `渲染回执.md`：每条的文件名、分辨率、耗时、状态。
4. 你按回执决定要不要重跑某一条。

## 分镜格式

```json
{ "title": "片名", "shots": [
  { "name": "01_hook", "prompt": "英文提示词", "width": 768, "height": 432,
    "length": 73, "steps": 8, "seed": 101 } ] }
```

- `name`：`两位序号_英文短名`，同片不重复。
- `prompt`：**英文**；中文会掉质量。
- `width/height`：必须能被 16 整除。低分辨率最快，定稿提高一档。
- `length`：帧数。24fps 下 **73 ≈ 3 秒**。
- `steps`：按渲染器文档给（配加速 LoRA 时通常 8）。
- `seed`：固定数字，同片内互不相同，方便复现与单条重跑。

## 提示词骨架

```
[风格锁] + 主体与动作 + 环境与光 + 一个运镜 + 质感 + Audio: ... + No text / no watermark
```

- 一条只讲**一个连续瞬间**、一个运镜动词。
- 风格锁逐字复用，这是跨镜头一致性的唯一杠杆。
- 负面固定带 `no text, no watermark, no subtitles`。

## 界面与文字

渲染器写不出可读文字。分镜里出现的屏幕、聊天窗、进度条，在提示词里一律 `no text`，并注明「界面后期合成」；
真实界面用截图或 HTML 渲染，不要指望模型画。

## 交付纪律

- 单次条目数按渲染器上限来（通常 6~12 条）。
- 一条不合格只重跑那一条，不整片重来。
- 不要声称已渲染；证据是渲染回执。
